# 頻出表現の追加・更新

`query-expansions.v1.json`を共通選定APIが組み込み、質問と呼出元が渡した英語から追加語句を作る。原文から表現を生成せず、外部モデル・辞書取得・検索は行わない。現在は数値境界4種、上限なし、レート制限、指数的な再試行待機、S3の通常バケットの8ルールを持つ。

各ルールは一意な`id`、完全な語句の`phrases`、追加する`aliases`、任意の対象条件`require_any`を持つ。`require_any`は一つ以上の語句が質問内にあることを要求する。S3の用語はS3/ListObjectsV2の文脈に限定する。単語内部・識別子内部には照合せず、直前のnot/never/withoutは保守的に除外する。これは自然言語の否定全般を理解する仕組みではない。

追加は定義順に最大4表現・512バイト。元の入力と合わせて4,096バイトを超える候補は追加せず、元の入力を切らない。追加した語句を使って別のルールを連鎖発火させない。BM25がすでに持つ単語だけの別表記は追加しない。元の入力に対する最大4件の`query_expansions`等の検証は従来どおり行う。

## 既定の適用条件

既定の`verified`は`verified-query-rules.v1.json`の承認に完全一致した場合だけ、指定されたルール集合を使う。それ以外は呼出元の英語だけを使う。承認には正規化後のリクエスト全体のSHA-256（質問・英語・予算・文書）、コードと依存関係のSHA-256、カタログのSHA-256、比較証拠のパス・ハッシュと保持した根拠単位を記録する。改善があり、従来保持した根拠を失わないことが必要。件数だけの増加では承認しない。

初期の2承認は、記録済みRedis/S3資料・従来英語・1,024トークンの個別条件に限定する。改善英語を使った未登録の資料に自動でルールを広げない。同一リクエストに複数の承認を合成することも禁止する。本文は照合用のハッシュに使い、英語や追加語句の生成には使わない。台帳とカタログはビルドへ組み込み、外部入力による承認・ホットリロードは行わない。コードや依存関係を変更したビルドで古い承認を使おうとするとエラーとなり、再検証を要求する。

`builtin`は全カタログを使う明示的な比較実験用。`--rule-ids`は`builtin`でのみ利用でき、未知のIDはエラーになる。APIの`query_expansion::expand`も全カタログを評価する低水準の比較用関数であり、製品の既定ポリシーではない。

## 更新手順

1. 実際の失敗から、頻出し、意味が等価な表現を選ぶ。単一のページの答え・数値・結論を追加しない。正式用語の対応は対象APIで限定する。
2. `version`を更新し、JSONにルールを追加・修正する。同じ失敗を再発させない正例と、否定・境界・別API・識別子等の反例を`tests/query_expansion.rs`へ先に追加して失敗を確認する。必要なら実際の選定結果を`tests/selection_cli.rs`でも検証する。
3. 全テスト、fmt、clippyを通す。語句を足すと無関係な段落の順位も上がり得るので、既知ケースの取りこぼし・悪化を検証する。
4. ルール・英語・質問を原文閲覧と選定より前に固定し、新しい未評価資料で無効/有効を比較する。生成指示を変えるときは、その効果も別条件にする。失敗例、標本の偏り、全条件を記録する。根拠保持と回答精度・請求額を混同しない。
5. 承認は条件ごとの比較結果をレビューして追加する。単独または実際に承認する集合で、無効時から保持根拠を失わず増やせることを確認する。今回の再現・台帳生成は`experiments/2026-10-22-verified-selection/verify.py --write-registry`で行い、再ビルド後に同スクリプトを引数なしで実行する。既知の正解に合わせた承認は未知資料での効果の証明とは扱わない。新しい資料や予算へ広げる場合は別条件として検証する。台帳だけを手で広げない。
6. 再ビルドした`jrg-select`を配置し、MCP/RTKプロキシを再起動して既存のセッション内キャッシュを破棄する。実行中のプロキシに対してバイナリだけを差し替えない。JSONのホットリロードは行わない。

定期的な改善時もこの手順を使う。ルールは自動で収集・採用・本番反映しない。

```sh
cargo test --test query_expansion --test selection_cli
cargo test
cargo fmt --all --check
cargo clippy --all-targets -- -D warnings
```

`jrg-select --query-rules off`は組み込みルールを無効にする。呼出元の英語や言い換えは残るため、ルールだけの比較に使える。ライブラリは`select_with_query_rules(request, QueryRuleMode::Off)`で同じ比較ができる。`query_expansion::expand`は追加語句・適用ルールID・版を返すため、更新の監査にも使える。
