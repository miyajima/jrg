# Codexで作業フォルダを自動選択する

`scripts/jrg-mcp.sh`は引数を省略すると、起動した場所の物理パスを検索rootにする。Gitルートやホームへ範囲を広げない。明示したrootを第1引数に渡す従来の使い方も維持する。

## 共通設定への導入

既存の`~/.local/bin/jrg`を利用する。設定を確認してから導入する。

```sh
python3 scripts/install-codex.py --dry-run --project-config .codex/config.toml
python3 scripts/install-codex.py --project-config .codex/config.toml
```

共通設定`~/.codex/config.toml`に、root引数・cwd指定のないjrg MCPを登録する。同時に、通常のコード調査・本文検索・範囲を限定した原文取得でjrgを優先する指示を追加する。既存の設定と指示は保持する。プロジェクト側に古い固定rootの登録がある場合は、`--project-config`でその登録も更新する。

この登録は実行用スクリプトの絶対パスを使う。リポジトリを移動した場合は再導入する。Codexの共通MCP設定は同じホストのデスクトップ・CLI・IDEで共有される。[公式MCP設定](https://learn.chatgpt.com/docs/extend/mcp)

既存のMCP接続には再接続が必要。検索rootはMCP起動時に固定されるため、チャットの作業フォルダを途中で変更した場合も再接続する。起動クライアントが渡した作業フォルダがrootになるので、導入確認では設定の存在だけでなく、対象フォルダの原文が返ることまで確認する。

全ファイル列挙、不存在確認、厳密な件数、機械出力・パイプ処理、未対応オプションや文字コードには通常のrgを使う。jrgを利用できない場合やroot外も、許可された通常ツールへ戻す。rgの実体・aliasは変更しない。

## 親・子フォルダとキャッシュ

| 作業フォルダ | 検索範囲 | 既存の埋め込みベクトル |
| --- | --- | --- |
| `~/projects/jrg` | jrg配下 | 同じファイル名・内容・モデル版なら再利用 |
| `~/projects` | projects配下 | 同じ内容は再利用。新しく対象に入るファイルは必要に応じて計算 |
| `~/projects/jrg/src` | src配下 | src内の同じ内容を再利用。親フォルダの原文は取得できない |

ベクトルのキーはモデル版・分割方式・ファイル名・チャンク内容から計算する。rootやフルパスを含めない。返却パスは毎回の検索対象から組み立てるため、キャッシュ再利用で別フォルダのパスが混ざることはない。ファイル内容やモデル版が変わると別のキーになる。

会話内の取得済み・未返却の範囲は、MCP接続ごとの一時セッションに保存する。別接続で原文が取得済みとして省略されることはない。保存済みのセッションを別rootへ転用するとエラーになる。

履歴による評価補正は別の永続データ。Git内のサブフォルダは同じリポジトリ識別を使うが、クエリ条件にcwdと対象パスも含むため、違う検索範囲を同じ問い合わせとは扱わない。Git外の親フォルダは独立した識別になる。

広いrootで対象パスを省略すると、広い範囲を検索する。埋め込みサービスの起動だけでは全フォルダを走査しないが、review時には要求されたパスを探索する。既知のパスや識別子で範囲を絞る。

## 動作確認

```sh
python3 -B tests/launcher.py
python3 -B tests/codex_install.py
python3 -B scripts/test_embedding.py
```

ランチャーテストは親・プロジェクト・src・symlinkの作業フォルダ、明示root、接続ごとのセッション分離と終了時の削除を検証する。インストーラーテストは有効な設定、既存設定・指示の保持、再実行、固定root登録の移行、dry-run、不正設定の保護を検証する。
