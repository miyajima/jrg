Prefer jrg retrieve for code investigation, source search, and bounded line reads within the configured root. Use native rg for exhaustive matches or file enumeration, absence checks, exact counts, machine-readable output and pipelines, or unsupported flags/encodings. If jrg is unavailable or a path is outside the configured root, use permitted native tools. Keep rg installed and usable; never replace its executable or alias it to jrg. Explicit user requests and host permissions take precedence.

For source investigations, use review with specific identifiers and narrow known paths. Batch independent known searches and reads; do not assume heuristic bundles contain every dependency or test. Use locate for discovery and explain for a named definition or guard. Follow concrete omitted-range hints with scoped reads rather than repeating broad searches.

Call shape: {"operations":[{"search":{"intent":"locate","patterns":["identifier"],"paths":["."]}}]}. Use search.patterns, never a top-level query; rank_query only ranks candidates. Paths must exist relative to the configured MCP root. Start with a known directory when the filename is uncertain; use search.globs for filename filters, then read a path returned in evidence. Omit paths for the root; do not send empty paths/patterns arrays. For review, omit context: a valid supplied value is ignored because review selects scopes. If a call fails, use its field/path and correction hint; do not repeat identical invalid arguments. Use permitted native tools for files outside this root.

For multiple requested items, supply requirements with stable IDs and literal original-source patterns. Preserve every linked condition clause in the answer. matched is literal evidence, not semantic coverage. Check unresolved, conditions_incomplete, omitted, syntax=unavailable, pending, and capture_omitted; ranked or budgeted results cannot prove absence. The same connection shares seen/pending state. Conditions can be resurfaced by reissuing a scoped operation; use repeat only when previously delivered source is needed again. Reconnects start a fresh retrieval session.

Smart retrieval records local metadata by default. Use a stable context_id for one task when available. structuredContent.history contains request_id and result_id values for optional feedback. Only report helpful/not_helpful after evidence from actual use; matching, delivery and a successful search alone do not establish usefulness. unknown retracts a prior report in the same context. feedback is always an agent report, never human confirmation; use a stable event_id for retries. History rechecks current source and only adjusts existing candidates for identical search conditions. history_mode=record records without reusing feedback; off disables both. The history tool reads local records within the configured root. No source bodies or embeddings are saved in history.
