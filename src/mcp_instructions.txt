Prefer jrg retrieve for code investigation, source search and bounded reads within the configured root. Use native rg for exhaustive matches/file lists, absence checks, exact counts, machine output/pipelines, unsupported flags/encodings, unavailable jrg or outside-root paths. Never replace/alias rg. User instructions and host permissions take precedence.

Define the required behaviors, complete guard clauses and relevant tests before retrieving. Use review with concrete identifiers and narrow known paths, locate for discovery, explain for a named definition/guard, then read only missing spans from returned paths/line hints. Avoid guessed large line chunks or whole files when functions are known; a small complete module may be appropriate. Batch independent needed scopes and tests, not speculative surrounding ranges. Heuristic bundles are not dependency/test closure. Keep every required condition and test; a smaller response alone is not success.

Scope first, budget second. max_tokens limits this result, not other outputs or the client's outer tool wrapper. Do not combine a large retrieval and a full alternate-file version/listing in one outer response; use a scoped diff for version comparisons and return large results separately. Check both inner omissions and outer truncation. Increase budget or fetch missing evidence if needed; never discard required clauses just to hit a token threshold.

Use operations:[{search:{patterns:["identifier"]}}] or read, not top-level query. Paths must exist relative to root; omit paths for root, never send empty paths/patterns. For unknown filenames use a known directory+globs, then returned paths. rank_query ranks only. Omit review context (valid values ignored). Correct errors using hints; never retry identical invalid arguments.

For multiple items, supply requirements with stable IDs and literal original-source patterns. Preserve every linked condition clause. matched is literal evidence, not semantic coverage. Check unresolved, conditions_incomplete, omitted, syntax=unavailable, pending and capture_omitted; ranked/budgeted results cannot prove absence. The connection shares seen/pending state. Reuse delivered evidence. Reissue scoped operations to resurface conditions; use empty operations with resume only for pending rows, not unselected/scope_limited hints. If prior source was lost to truncation/compaction or is needed again, use repeat:true on that exact scope; a normal reread may suppress seen rows. Do not repeat broad searches or reconnect merely to reset seen state.

Smart retrieval records local metadata, not source bodies/embeddings. Use stable context_id. structuredContent.history IDs support optional feedback after actual use: delivery/matching alone is not helpful evidence. Feedback is an agent report, never human confirmation; use stable event_id for retries. unknown retracts a report. History rechecks source and ranks only identical-condition candidates; record mode logs without reuse, off disables both.
