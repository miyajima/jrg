# jrg内蔵BM25順位付けの実装と開発用再生

2026-10-16 JST。`--smart --rank-query QUERY`を追加した。通常の文字列・正規表現検索で保持した候補の中で順位を付け、元の表記と行番号を返す。指定しない場合の動作は維持する。OrgBrainの製品コード、インストール済みバイナリ、共有設定は変更していない。

## 実装した動作

- BM25はLucene方式、k1=1.2、b=0.75。要求内の候補の語頻度と長さから計算する。永続索引、外部モデル、追加辞書は不要。
- 順位付け用にNFKC、カナ統一、小文字化を行う。英語識別子は全体に加えてsnake_case、camelCase、略語、数字の境界の分割語を登録する。日本語は連続文字列と隣接2文字を使う。Sudachiによる形態素解析、翻訳、埋め込みは追加していない。
- 一致行と指定文脈、または既存explainの範囲を隣接する原文範囲へまとめ、4,000 Unicode文字を目安に行境界で分ける。単一の長い行は分割しない。チャンクの重複はない。
- 同点はパスと行範囲で決める。未知語のクエリでも候補を捨てない。空白・記号だけのクエリは終了コード2。
- 出力予算に収まらない候補はクエリに合う行を先に返す。原文行を途中で切らず、`pending`、`partial`、`capture_omitted`を保持する。sessionで残りを取得できる。
- batchは外側に一つのクエリを指定し、明示readを含めた全候補を順位付けする。操作内の指定は拒否する。現行の構造化MCPには公開していない。

Python版のBM25S実験とは語分割、候補範囲、重複、統計の対象が異なる。以前の「上位10件の取得率95%」をこの製品実装の実測値として扱わない。

## 開発用10クエリの診断

既存BM25実験の**開発用**5話題×日本語・英語の候補順位付け10クエリを再利用した。評価用40件は参照・再実行・調整に使っていない。これは既知の問いによる診断であり、独立した初見評価ではない。

実行前に`protocol.json`へ質問・既存の正解訂正・ソース一覧とハッシュ・製品ソースとバイナリのハッシュ・順序・条件を固定した。4プロジェクトの既存固定ソースを明示ファイル一覧で指定し、内蔵エンジン、1スレッド、前後8行、2,000トークン、各方式1回とした。実モデルは起動していない。

主指標は、登録した正解パスの**全原文行範囲が2,000トークン以内の出力に含まれたか**。候補チャンクのRecall@10でも、AIの回答正答率でもない。

audioの2件は各50,874行、parcelsの2件は各1,407行の収集省略があった。検索の保持上限は既存の4,096行・8MiBのままであり、保持できなかった候補を順位付けで復旧する効果はない。上限到達前に対象パスや検索語を絞る必要がある。保持した集合の安定性を超えて、並列検索で常に同じ上位結果になる保証はしない。

## 再実行

ソース一式と元の固定スナップショットがあるローカル環境で、**別の実験ディレクトリ**に`evaluate.py`をコピーする。元の`protocol.json`と`raw/`を消して再実行しない。スクリプトは同じexperiments階層で使う。

```sh
cargo build --release --locked
experiments/2026-10-16-bm25-evaluation/.venv/bin/python experiments/NEW-COHORT/evaluate.py
experiments/2026-10-16-bm25-evaluation/.venv/bin/python experiments/NEW-COHORT/evaluate.py --run
```

`protocol.json`が事前登録、`raw/`が各呼出しの実行意図・原文出力・記録、`results.json`が集計。原文出力と質問データはローカルに保持しGit対象外とする。設定変更後の比較は別コホートとして記録し、評価用データを見て設定を調整しない。
