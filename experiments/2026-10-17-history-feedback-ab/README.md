# jrg検索履歴・フィードバックの実タスク比較

実施日: 2026-10-17

## 結論

**今回の条件では、評価の蓄積による検索精度・調査時間の改善を確認できなかった。**

蓄積ありの点数・時間は数値上よかったが、実際の調査で発行された検索を同じ順序で両条件に流すと、
正常な148応答の返却原文はすべて同一だった。エラー応答5件も同一。
元の各調査の応答も153件すべて再現できた。
今回の補正は、調査モデルへ渡す根拠を変えていない。
モデルの調査経路・推論量・回答量の違いを、評価補正の効果とは判定しない。

加えて、継続取得のpanicと、通常検索での履歴保存失敗を再現した。
現状の機構は履歴・評価を扱う基盤であり、使い続けるだけで精度と速度が上がるという主張を支える結果ではない。

## 比較条件

- 実リポジトリ由来のソースレビュー5課題: smart経路、土地候補、音声処理、配布物、日本語検索。
- 先に独立した5調査を実行し、正しい回答の出典として実際に使われ、返却履歴もある結果だけを評価。
  `agent/helpful`を314件蓄積。人の評価は模擬していない。306個のquery/anchor/contextに相当する。
- A: 履歴記録は有効、蓄積済み評価なし。B: 同じモードで、課題別の固定済み評価を使用。
- 各課題2組、順序を反転した計20調査。すべて新しい会話。同じroot・原文・バイナリ・質問・モデル指定・予算。
- モデル指定: `gpt-6.1-sol` / `high`。提供側の不変なモデル版は観測できない。
- 最初の検索は事前調査の実際の初回検索を両条件で共通化。その後は自由に調査。
  20試行すべてで初回検索条件の一致を確認した。事前回答や正解表は渡していない。
- 測定中に評価を追加しない。MCP中継処理は原文・条件・予算を保ち、履歴情報と管理ツールを隠す。
- 答えは条件名を隠して、各課題の要求6項目と原文に照らして親セッションが採点。
  採点用の追加モデルは起動していない。引用699件のファイル・行範囲もすべて有効。
- **EmbeddingGemma2は両条件とも無効。** 実行可能なオフラインモデル／サービスを確認できなかった。
  ASTと文字検索の上に載る履歴補正の検証である。

固定した関連範囲以外にも有用な補助コードがあるため、関連行の割合は検索全体の絶対的な精度ではない。

## 補正そのものが変えたもの

### 事前調査の検索を再実行

40呼出しのうち正常39件と入力エラー1件を、両条件で同じ順序で再実行した。
`history_applied`の観測値合計はBで46だったが、本文の変化は0件。
配布物・日本語検索では補正適用が0だった。

### 実際の20調査の検索経路を再実行

モデルの手順の違いを固定するため、各調査の応答ログにある検索を、別のA/B状態で再実行した。
これは事前検索の再実行後に登録した補助検証で、追加モデル実行は0回。

| 検証 | 結果 |
| --- | ---: |
| 再実行した応答 | 153件（正常148・入力エラー5） |
| A/Bで本文が変化 | 0件 |
| 履歴メタデータで比較できた選択範囲 | 113件、変化0件 |
| 元の調査と同じ条件の応答を再現できなかった件数 | 0件 |

接続切れで応答がなかった2呼出しはこの再実行には入らず、別途エラーとして集計した。
Bの実調査では、評価付き履歴に条件が一致した記録済み検索は8件、
そのうち補正適用が観測されたのは4件（応答68件の約5.9%）、`history_applied`合計36だった。
評価を増やすだけで補正幅が増え続ける実装ではなく、agent評価の最大補正は2.5%。

**同じ検索経路なら返却内容が同じなので、今回の点数・時間差を評価による改善とする根拠は得られない。**

## 見つかった不具合と制約

1. **履歴autoの`resume`でpanicしMCP接続が落ちる。**
   パターンなしの継続取得で`Args::inputs`がunwrapする。終了101、応答なし。
   同じ要求を履歴offにすると正常終了。実調査でも1回答中に2回の`Transport closed`を記録した。
2. **履歴メタデータの64KiB上限で通常検索の履歴が保存されない。**
   事前の正常39呼出し中9件（23.1%）で失敗し、履歴は30件だけだった。
   同条件の両再実行でも9件ずつ上限エラーを確認。保存されない結果には評価を付けられない。

詳細と再現結果は [ISSUES.md](ISSUES.md)。
今回の比較は固定版の検証であり、プロダクト実装の修正は行っていない。

## 費用と適用範囲

- 評価収集用5調査の実行時間は合計619.4秒（10分19秒）。原文確認・採点の作業時間は別で、正確には計測していない。
  評価試行の時間には混ぜていない。効果が実証されていないため、回収回数は算出しない。
- 同じ課題の再調査5件・10組の記述的比較。未知の質問、言い換え、別予算への一般化は測定していない。
- 314件は正のagent評価のみ。人の10%補正や負の評価、EmbeddingGemma2併用の効果は未検証。
- 2課題は現jrgの凍結版、3課題は保存してあった2026-10-15の実コード。
  `.git`を持たない同一パスの隔離コピーで比較した。実worktreeや編集中の運用をこの数値から一般化しない。
- コードとテスト定義の静的照合で採点した。各プロジェクトのテスト実行・本番・実デバイス検証は含まない。
- バイナリ・原文・質問・中継処理・正解表・評価データのハッシュは一致。
  評価データへの追加書込なし、許可外ツールの使用なし、凍結ソースへの追加・変更なしを確認した。

## 次に優先すること

まず継続取得のpanicと履歴保存の欠落を修正する。
精度と調査全体の時間を改善するには、順位への小さな補正に加えて、
**検証済みの検索手順・必要範囲を、現在の原文を確認して再利用する機構**を別に検証する必要がある。
測定目標は、必要な条件を保持したまま、読取量とモデルの追加調査を減らすこと。
