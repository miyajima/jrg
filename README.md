# jrg — 日本語の表記ゆれと AI 入力に対応する検索 CLI

Rust 製の再帰テキスト検索ツールです。`がっこう` で `ガッコウ`、`ｶﾞｯｺｳ`、結合濁点の `がっこう` も見つかります。検索結果は元の表記を保ち、一致箇所を元の文字に対応付けて表示します。

複数項目の調査では、MCP／batchに`requirements`を指定すると、依頼項目と原文・条件式の対応表を先頭に返します（0.15.0）。複数行の条件式をまとめて優先表示し、未取得・予算による省略を明示します。[引数・出力と限界](docs/CODEX_RETRIEVAL.md)を参照してください。

## 自動選択して調査する（0.8.0）

0.15.1では構文解析結果・トークナイザー・予算判定の計数を再利用し、取得順と全体予算を維持したまま再計算を減らします。[今回の固定ログによる速度・返却本文・取得済み状態の検証](experiments/2026-10-17-integration-cache/REPORT.md)を参照してください。

`--smart` は、検索の意味を保てる範囲で検索エンジンと出力形式を選びます。

```sh
jrg --smart がっこう ./docs
jrg --smart --regex --intent explain 'initial_input_deadline_control' ./src
jrg --smart --regex --intent explain -A 6 'reserve|claim' ./src
jrg --smart --max-tokens 1000 認証 ./docs
jrg --smart --regex --explain-plan 'fn deadline' ./src
```

- NFKC・カナ統一が必要な固定文字列検索は内蔵エンジンを使います。ASCIIの `API` でも原文の `ＡＰＩ` に一致する意味を保つため、単純な文字種判定でrgへ切り替えません。
- `--regex` または `--no-normalize` の原文検索で、対応するファイル入力・出力モードなら外部の `rg` を使います。rgがPATHにないときは内蔵へ戻ります。rgの実行エラーは再検索で隠さず終了コード2にします。
- 標準入力、Shift_JIS/EUC-JP、JSON・集計などの専用モード、改行を含むパターン等は内蔵側へ残します。rgは `--no-config`、`--no-require-git`、`--crlf` を付けて実行し、JSON結果をjrgのイベントへ変換します。
- `--smart --intent explain` は文脈が未指定なら、関数・メソッドや条件分岐のまとまりを原文の行番号付きで返します。`-A` / `-B` / `-C` を明示すれば従来の行単位の文脈を優先し、`-C0` で追加を止められます。smart以外のexplainは前後3行です。
- 短い結果は完全な通常形式を使います。明示した1ファイルだけなら、rgと同様にパスを省いた `行番号:本文` 形式になります。予算内で完全に表現できる圧縮形式がさらに短い場合はそちらを使います。
- 長い結果は `o200k_base` の予算内へ圧縮します。予算が足りなければ本文や文脈も省略します。集計の `omitted` / `clipped` に加え、`context_omitted` / `context_clipped` で文脈の欠落を示します。

`--smart` のlocate既定は上限8,000トークン・抜粋320書記素、関数文脈を返すexplainは16,000トークンです。`--max-tokens`を明示すればその値を優先します。通常形式と圧縮形式が切り替わるため、機械処理には従来の `--json`、固定したAI出力形式が必要なら `--ai` を使ってください。両者の出力契約は維持しています。`--smart` と `--ai` は同時指定できません。`--smart` も、元の検索結果をすべて返す保証がある全件列挙には使わないでください。

### ファイル選別後に関数・条件分岐・関連テストを一括取得（0.11.0）

`--smart --intent review`は、行番号を推測してファイル全体を読む代わりに、検索に一致した関数・分岐、同じファイルの小さな補助関数・定数・型、関連テストをまとめます。MCPのsearchでも`intent:"review"`を指定できます。独立したreview操作は同じretrieveにまとめてください。

```sh
jrg --smart --intent review -i -e cancel -e drain --rank-query 'audio cancel stale effect drain completion' ./src
```

実装ファイル名に対応するテストを先に探し、不足分はモジュール名・一般名を除く実装識別子の参照で補います。stage/verify等の一般名だけで全体のテストを広げず、テストだけの指定からも全体へ広げません。関連付けは字面と命名規則による推定です。AST・呼出しグラフ・意味による依存関係や、すべての関連テストを取得した証明ではありません。初期版はUTF-8のRust、TypeScript/JavaScript、Pythonを対象にします。

ディレクトリのreviewは各ファイル最大16一致行のプレビューとパスをBM25で評価し、最大3ファイル・最高点の25%以上へ絞ってから関数を展開します（rank_query省略時は検索語を使用）。明示したファイルはこの選別の対象外です。バッチ全体で実装8範囲・テスト6範囲、小さな補助関数／型8件、定数16件までを共有します。関数が256行／12,000バイトを超える場合は宣言と条件分岐へ絞り、`scope_limited`と全体の読取範囲を示します。型は96行、補助関数は64行までで再帰展開しません。取得済み範囲は候補選択前にも除外し、変更があれば再取得します。

`# bundle source=... tests=... helpers=... omitted=...`と未選択範囲の案内を確認してください。選ばなかった候補はpendingではなく、tests=0もテスト不存在の証明ではありません。既定予算はCLI/MCPとも24,000、MCP最大26,000を維持し、返却は96,000バイトも上限とします。既読記録前に制限し、不足本文はpendingへ残します。外側の上限・計数は呼出し元にも依存します。reviewは128以上の枠が必要で、明示contextと旧来文字コード・標準入力には対応しません。返却済みの原文と行番号を再利用し、欠けている要件だけを狭いexplain/readで確認してください。

### 広い探索をBM25の上位候補に絞る（0.9.0）

文字列検索で候補が多い場合は、`--rank-query`で調査内容を指定すると、保持できた原文候補をBM25関連度順に返します。候補を取得する検索語・正規表現と、順位付けのクエリは別です。

```sh
jrg --smart --regex -C 3 --rank-query 'cancel audio stale effect' 'cancel|effect' ./src
jrg --smart --rank-query '認証 期限 トークン' -C 2 認証 ./docs
jrg --smart --rank-query 'cancel audio' --session /tmp/investigation.json --max-tokens 24000 --discovery-limit 12 cancel ./src
```

- `--smart`専用の任意機能です。指定しなければ従来の検索・整形を維持します。通常検索のNFKC・カナ統一・大小文字・ignore・glob・文字コードの条件は変えません。検索で取得しなかった候補を復旧する機能ではありません。
- 順位付けはNFKC・カナ統一・小文字化した語を使い、英語識別子は元の語に加えてsnake_case・camelCase・略語・数字の境界で分割します。日本語は連続文字列と隣接2文字を使います。形態素解析、翻訳、同義語展開、埋め込み検索は行いません。日本語の質問から英語だけの実装を探す効果は保証しません。
- 取得済みの一致行と明示した文脈、またはexplainで選んだ範囲を、隣接する原文範囲にまとめます。約4,000 Unicode文字ごとに行境界で分割します。単一の長い行は分割しません。パス名はスコアへ入れません。
- BM25はLucene方式、`k1=1.2`、`b=0.75`。語の頻度と長さの統計はその要求で保持した候補から計算します。クエリ内の重複語は加重しません。同点はパス・原文行順です。未知語だけなら同点のパス・行順となり、候補上限も適用します。空白・記号だけのクエリはエラーにします。
- 出力は`@ path:開始-終了`と原文行、関連度順です。予算不足ではクエリに合う行を優先して部分返却し、`pending` / `partial` / `capture_omitted`で欠落を表示します。`--session`の未表示範囲は`--resume`で回収できます。検索や収集の上限があるため、順位や結果から不存在を断定しないでください。
- `rank_query`付きのlocateでディレクトリまたは複数ファイルを探す場合、操作ごとに新しい候補の上位12範囲を返します。CLI外側の`--discovery-limit N`、MCP外側の`discovery_limit`で0〜256を指定でき、0は制限なしです。取得済み行と同じ要求の必要範囲だけで埋まる候補を、選別前に除きます。候補の数であり、行数・関数数ではありません。
- 明示read、単一ファイルのlocate、explainで選んだ関数・分岐は候補制限の対象外です。広い探索とまとめた要求ではこれらを先に詰め、残りへ上位候補を返します。既定の大きな出力枠は維持しますが、最終予算・収集上限・explainの局所化は引き続き適用します。
- `discovery_selected` / `discovery_omitted`は選別した候補数です。外した範囲の案内を最大16件、予算に入る分だけ返します。これらは`pending`にも既読にもせず、resumeで探索全体を戻しません。必要な案内だけをread、または単一ファイルの検索で取得してください。予算で切れた選択済み範囲は従来どおりpendingです。
- batchでは**外側**に`--rank-query`、MCPではretrieveの外側に`rank_query`を指定します。操作内の指定はエラーです。候補制限を0にするか、広いlocateがない要求では従来の全候補の順位付けを維持します。

永続索引・Python・追加辞書・モデルのダウンロードは不要です。このRust版は、以前のBM25S実験とは語分割・候補範囲が異なります。実験の取得率95%をこの機能の測定結果として扱わないでください。

[開発用10クエリの再生結果](experiments/2026-10-16-native-ranking/REPORT.md): 2,000トークン以内に正解原文範囲を返せた件数は従来2件→BM25付き5件でした。ただし日本語の1件は取得できなくなり、広い検索4件では収集上限に達しています。初見課題全般の改善や既定への採用を示す評価ではありません。

### 関数の文脈と一括取得

explainはRust/JavaScript/TypeScriptの括弧・文字列・コメント、Pythonのインデントを手がかりに範囲を選びます。ASTや呼出関係の解析ではありません。小さな関数は全体を、長い関数は宣言と一致を含む分岐を返します（目安は256行・12,000バイトまで）。大きな分岐も収まらなければ一致行を返します。`@ path:開始-終了`と元の行番号を付け、重複範囲をまとめます。単独のexplainで範囲が予算に収まらない場合は途中で切らず、`deferred`に位置を示します。一括取得・セッションでは部分返却と`pending`を使います。全てのUnicode・構文・離れた依存先を含む保証はありません。通常ファイル以外・別文字コードは取得済みの行文脈を維持します。

0.8.0では、同じ検索で関数の宣言に一致した場合、定義を保持し、呼出し箇所は呼出し元の宣言と前後3行へ絞ります。定義が別ファイルにある場合も適用します。定義が見つからない検索、明示文脈、`--explain-scope full`は従来の選択を保ちます。関連テストの自動収集や意味解決ではありません。

`jrg --smart --mcp --root /absolute/project --session /private/tmp/task-session.json`で、検索と行読取をまとめるローカルMCPを利用できます。`retrieve`の構造化引数を直接渡すため、シェル用JSONの手書きを省けます。セッションを会話ごとに分け、既読範囲を共有します。既定予算24,000、最大26,000です。[接続と呼出し手順](docs/CODEX_RETRIEVAL.md#080-構造化したmcp呼出し)を参照してください。

0.7.0の`--explain-scope auto`（既定）は、各ファイルで関数展開が256行を超え、かつ一致の前後3行の合計の4倍を超える場合、宣言・最大64行の局所分岐・一致近傍へ絞ります。一致行は残し、`scope_limited`と`scope_read path:開始-終了`で関数全体を返していないことを示します。これは予算による保留とは別で、resumeの対象にはしません。必要なら示された範囲をreadするか、`--explain-scope full`で従来の範囲選択を指定します。batchでは外側のこの指定を継承し、操作内の明示指定を優先します。汎用語の広い正規表現はlocate、既知の関数・ガードの確認はexplainを推奨します。

独立した検索・既知の行範囲の読取を、1回の呼出しでまとめられます。シェルコマンドは受け付けません。

```sh
jrg --smart --batch - <<'JSON'
{"operations":[
  {"search":["--regex","--intent","explain","receive_parcels","src/parcels.rs"]},
  {"search":["--regex","--intent","explain","fn .*reject","tests"]},
  {"read":{"path":"README.md","start":1,"end":35}}
]}
JSON
```

- `search`はjrgの検索引数の配列です。`--smart`は自動で付与します。各検索のフラグは配列内で指定します。外側から継承する検索フラグは`--explain-scope`だけです。パス省略時はカレントディレクトリです。
- `read`はUTF-8通常ファイルの1始まり・終端を含む行範囲です。終端がEOFを超えればEOFまで返します。検索で取得した範囲と重なる読取や、同じファイルの別表記も重複表示しません。離れた範囲は`@ path:1-3,8-10`のように列挙し、返していない間の行を含むとは表現しません。
- 一括出力全体の既定予算は24,000トークン。`--max-tokens`で変更できます。`deferred`、`capture_omitted`、`errors`を確認し、欠落がある結果から不存在を断定しないでください。個別エラーでも後続処理を続け、終了コード2とエラー集計を返します。一致なしは個別に表示し、全処理にエラーがなければ一括実行は0で終了します。
- 1要求は最大64操作・JSON 1MiB。文脈キャッシュは各ファイル4MiB、合計16MiB・20万行まで。1検索の保持は4,096行・8MiBまでで、超過は明示します。ネストしたbatchや標準入力の検索は受け付けません。
- 一括要求内の読取だけを共有し、呼出しを越えたキャッシュ・永続インデックス・自動モデル呼出しは追加しません。

0.4.1では、必要な関数範囲を広い読取範囲より先に選び、予算判定前に大きな範囲へ統合してしまう動作を修正しました。表示できた原文行だけを重複扱いにするため、広い範囲が予算を超えても、小さな関数や分岐を表示できます。検索引数のエラーも操作ごとに記録し、同じ一括要求内の有効な読取を残します。JSON構造自体が不正な場合は全要求を拒否します。batch内で使えるのは内容検索の引数で、ファイル一覧などの専用モードは対象外です。

### 呼出しをまたぐ範囲管理（0.5.0）

同じ会話の検索・読取で`--session FILE`を共有すると、既にstdoutへ返した原文行を次の呼出しから除外します。状態には原文を保存せず、正規パス・内容の指紋・表示済み／未表示の行範囲を記録します。一括取得・セッションでは、全候補の収集後、返却直前に重複を除きます。全行が予算内ならファイルごとにまとめて一度に返し、超える場合は関数範囲・検索の一致行・明示readの順で原文行を詰めます。大きい範囲を丸ごと保留せず、入った行だけを表示済みにします。部分出力は`partial`と`pending`で示すため、関数全体を返したと解釈しないでください。

```sh
jrg --smart --session /tmp/my-investigation.json --batch - <<'JSON'
{"operations":[{"read":{"path":"src/search.rs","start":1,"end":300}}]}
JSON
jrg --smart --session /tmp/my-investigation.json --resume
# 必要なファイル・行だけなら、同じsessionで狭いreadを指定する
# 取得済みの内容を再度確認したい場合は --repeat を付ける
```

- `--resume`は保存した未表示範囲だけを読み、検索を再実行しません。元の範囲を同じreadで要求しても、既に返した行は重複しません。予算が小さく1行も入らない場合はpendingのままなので、`--max-tokens`を増やしてください。
- 同じ通常UTF-8ファイルの別名も統合します。内容が変われば表示済み範囲を無効化します。resume中に変更を検知した場合は古い行範囲を捨てて通知するため、元の検索・readをやり直してください。追跡できない入力は`untracked`で示し、呼出しをまたぐ重複排除の対象にしません。
- 状態は同じ作業ディレクトリ・同じjrg版・同じ会話だけで共有します。別会話やコンテキストを失った後は新しいセッションを使うか`--repeat`で取り直してください。CLIがstdoutへ書けたことは、呼出し側の出力上限でモデルへの入力が切られていない保証ではありません。ツールの出力枠を同じ呼出しで返す全出力の合計以上に設定し、切られた場合は`--repeat`で必要範囲を再取得してください。
- 0.6.0の既定予算はlocate8,000、explain16,000、batch/resume24,000です。明示した小さい予算はそのまま尊重します。`--ai`の既定2,000は維持します。収集の安全上限は別に維持します。セッションは8MiB・4,096ファイル以内、排他ロックと一時ファイルのrenameで保存します。既存状態の破損・版／作業場所の不一致・ロック競合は、黙って初期化せずエラーにします。Unixでは状態とロックを0600で作ります。指紋は変更検知用で、改ざん検証・認証用ではありません。
- 自動で全ユーザー共通の状態を作ることはありません。検索対象へ状態ファイル自身を混ぜないため、プロジェクト外か隠しファイルのパスを推奨します。通常検索・既存`--ai`・`--json`の出力契約は維持します。batchはsessionなしでも最終整形・部分返却を使います。

0.6.0では、予算不足の往復を抑えるためsmartの既定枠を広げました。実装の一致行を広い文書readより優先し、隣接行と離れた範囲のパス見出しを共有します。予算を広げても必ずその量を返すわけではなく、短い結果は短いままです。AIから使う場合は、実行ツール側の出力枠も一括24,000トークン以上（同じ呼出しに複数結果があれば合計分）にしてください。後段で切り詰められるとCLI側の拡大だけでは往復を減らせません。

Codexの`functions.exec`を通す場合は、外側の既定10,000トークンにも注意が必要です。[Codexからの取得手順](docs/CODEX_RETRIEVAL.md)のように、外側30,000・内側26,000を明示し、`text(result.output)`で原文だけを返します。jrgから外側の上限を変更することはできません。

`--engine auto|native|rg` で選択を指定できます。自動でrgへ切り替わるのは `--smart` 使用時です。`--engine rg` で正規化などの非対応条件を強制した場合はエラーにします。`--explain-plan` は、実際のエンジン・理由・文脈量をstderrへ表示します。通常形式を維持する従来の呼び出しや `jrg-ai` の動作は変えていません。`jrg --files` は未対応です。

rgを導入しなくても内蔵エンジンだけで動きます。`--smart` は適合する経路を決める保守的な規則であり、実タスクの最小入力トークン数を保証する最適化器ではありません。日本語の表記ゆれ対応と、言語を問わない出力予算の制御は別の価値です。

## AI に渡すトークンを抑える

```sh
jrg --ai --max-tokens 1000 認証 ./src
jrg --ai --snippet-chars 80 -e 東京 -e 京都 ./docs
jrg --ai --regex 'TODO|FIXME' ./src
```

`--ai` は次のように結果を圧縮します。

- パスをファイルの先頭に一度だけ表示する。
- 同じファイル内の完全に同じ原文行をまとめ、行番号を保持する。連続した位置は範囲にする。
- 長い行は最初の一致の周辺を抜粋する。既定は最大 160 書記素、予算が不足すればさらに短くする。
- 一致行を文脈行より優先し、候補ファイルごとに 1 グループずつ順番に予算を割り当てる。
- 全体を `o200k_base` で計測し、ヘッダー・改行・末尾集計も含めて `--max-tokens` 以内に収める。既定は 2,000、指定範囲は 64〜1,000,000。

同じ原文が 1、2、4 行目にある場合:

```text
@ src/auth.rs
1-2,4:1:認証を再試行します
# matched=3 shown=3 omitted=0 clipped=0
```

`行番号:開始列:抜粋` の形式です。開始列は、抜粋本文の最初の文字の、原文での Unicode 文字位置（1 始まり）です。追加した `…` は列に含みません。文脈行には `~` を付けます。制御文字はエスケープし、色コードは出力しません。

- `matched`: 検索で選択した一致行数（`-v` では選択した不一致行数）。
- `shown`: 行番号を表示した一致行数。重複を範囲にまとめた場合も元の行数で数える。
- `omitted`: 予算・候補制限によって出力しなかった一致行数。
- `clipped`: 表示した一致行のうち、本文の一部を `…` で省略した行数。

`omitted=0` でも `clipped>0` なら原文の一部を省略しています。長い行に複数の一致がある場合、後方の一致は抜粋に含まれないことがあります。長い検索語自体も抜粋幅に収まらなければ途中で切れます。予算不足で一部の行番号だけを表示した場合も、残りは `omitted` に計上します。必要に応じて対象ファイルに絞って再検索するか、`sed -n '10,30p' src/auth.rs` などで原文を確認してください。

このモードは検索終了後にまとめて出力します。並列検索でも同じ候補集合なら結果は同じ順序です。候補は最大 4,096 グループ、各グループの位置は最大 256 区間に制限し、超過分も `omitted` に含めます。連続した同一行は位置の区間数を増やさずに保持できます。候補上限に達した場合は、一致行、パス、本文、行番号による辞書順の先頭を保持します。`-m` で検索自体を打ち切った範囲より後の行は `matched` に含みません。

トークン上限は **stdout 本文の `o200k_base` トークン数**です。モデル固有の tokenizer、API のメッセージ枠、stderr のエラー表示などは含みません。通常出力より必ず短くなる保証はなく、ごく少ない一致では集計の分だけ増える場合があります。辞書は実行ファイルに埋め込み、実行時の通信や外部 AI API は使用しません。正確な計測と全件走査のため、通常モードより実行時間とメモリを使います。

通常出力や JSON が必要なら `--ai` を外してください。`--ai` は `--json`、`-c`、`-l`、`-q`、`-o`、`--no-line-number`、`--column` と併用できません。`--max-tokens` と `--snippet-chars` は `--ai` 専用です。

## 日本語検索の仕組み

既定では検索語と各行に **NFKC → カタカナをひらがなへ統一** の順で変換を適用し、固定文字列として検索します。

| 検索語 | 一致する表記の例 |
| --- | --- |
| `がっこう` | `がっこう` / `ガッコウ` / `ｶﾞｯｺｳ` / `がっこう` |
| `ＡＰＩ` | `API` / `ＡＰＩ`（`-i` なら `api` も） |
| `株式会社` | `株式会社` / `㍿` |
| `123` | `123` / `１２３` / `①23` |

NFKC は幅や濁点のほか、丸数字・合字・単位記号などの互換文字も統一します。原文との対応には書記素クラスタを用いるため、`が` の一致を `ｶﾞ` 全体に、`社` の一致を `㍿` 全体に対応付けます。同じ原文字への重複した一致はまとめます。

`--no-kana` でカナ統一だけを、`--no-normalize` で両方の変換を無効にできます。英字の大文字小文字は既定で区別し、`-i` で無視します。`-S` は正規化した検索語に大文字が含まれるときだけ区別します。

漢字の読みや同義語は扱いません。`がっこう` と `学校`、`高橋` と `髙橋` は別の文字列です。長音や小書き文字も区別します。

形態素解析による分かち書きや、単語境界を考慮した日本語検索には未対応です。中国語・韓国語も Unicode の文字列として検索できますが、簡体字・繁体字の相互検索など、言語固有の処理は行いません。AI 出力のトークン計測は、検索用の分かち書きとは別の機能です。

## よく使うオプション

| オプション | 動作 |
| --- | --- |
| `-e 語1 -e 語2` | 複数の検索語を OR 検索 |
| `-F` | 固定文字列検索（既定） |
| `--regex 'TODO\|FIXME'` | **原文**に対する正規表現検索。正規化は行わない |
| `-i` / `-S` | 大文字小文字を無視 / スマートケース |
| `-g '*.md'` / `-g '!vendor/**'` | glob による対象指定 / 除外 |
| `--hidden` / `--no-ignore` | 隠しファイルを含める / ignore 規則を無効化 |
| `-l` / `-c` / `-q` | ファイル名のみ / 一致行数 / 終了コードのみ |
| `-o` / `-v` | 一致部分のみ / 一致しない行 |
| `-C 2` / `-B 2` / `-A 2` | 前後 / 前 / 後の文脈を表示 |
| `-m 10` | 各ファイルで選択する一致行の上限 |
| `--column` | 元の行での開始列（Unicode 文字数、1 始まり） |
| `--no-line-number` | 既定の行番号を省略 |
| `--encoding utf8\|shift-jis\|euc-jp` | 入力文字コードを指定（既定 UTF-8） |
| `--json` | JSON Lines 出力 |
| `--ai` | AI 向けの圧縮出力 |
| `--max-tokens 1000` | AI 出力全体の o200k_base トークン上限 |
| `--snippet-chars 80` | AI 抜粋の最大書記素数（16〜4,096） |
| `-j 4` | 並列検索数（既定は利用可能 CPU 数、上限 12） |
| `--color auto\|always\|never` | 一致部分の色付け |

正規表現の実行例は `jrg --regex 'TODO|FIXME' src` です。正規表現では構文を保つため、パターンも検索対象も正規化しません。Rust `regex` の構文を使用し、後方参照や look-around は使えません。

`-e` を使った場合は位置引数をすべて検索パスとして扱います。`jrg -e 東京 -e 京都 docs` は docs 内を検索します。

## ファイルと標準入力

パスを省略すると、標準入力がパイプの場合はその入力を、それ以外はカレントディレクトリを検索します。明示的な `-` も標準入力です。

```sh
printf 'ガッコウ\n' | jrg がっこう
jrg がっこう - docs/notes.txt < input.txt
jrg -e 東京 -e 京都 ./docs
jrg --regex 'TODO|FIXME' ./src
```

ディレクトリは再帰検索し、既定で `.gitignore`、`.ignore`、`.git/info/exclude`、Git のグローバル除外を適用します。Git リポジトリ外の `.gitignore` も有効です。隠しファイルは省略し、ディレクトリ内のシンボリックリンクは辿りません。**肯定の `-g` は明示的な包含指定なので、ignore と隠しファイルの規則に優先します**（rg と同じ挙動）。

UTF-8 BOM と CRLF に対応します。Shift_JIS（CP932）・EUC-JP は `--encoding` で選びます。曖昧な文字コードの自動推定は行わず、不正なバイト列はエラーにします。UTF-16/32 は未対応です。バイナリ判定は初期バッファ（最大 8 KiB）の NUL の有無によるもので、`-a` で無効にできます。

## 出力形式

通常は `パス:行番号:元の行`、文脈行は `パス-行番号-元の行` です。パスは常に出力します。並列処理のためファイルの出力順は不定で、異なるファイルの行が交互に出ることがあります。各行の出力自体は分割されません。

`--json` の例:

```json
{"type":"match","path":"notes.txt","line_number":1,"text":"前ｶﾞ後","submatches":[{"start":3,"end":9,"column":2,"text":"ｶﾞ"}]}
```

`start` / `end` はデコード後の元の行（BOM・改行を除く）の UTF-8 バイト位置で、0 始まり・終端を含まない範囲です。Shift_JIS などの入力バイト位置ではありません。`column` は 1 始まりの Unicode スカラ値の位置で、表示幅・書記素数ではありません。文脈行の `type` は `context` です。

終了コード: **0 = 一致あり、1 = 一致なし、2 = エラー**。`-q` は一致を見つけた時点で 0 を返します。パイプの読み手が閉じた場合も正常終了します。

## rg との関係と性能

これは日本語検索を優先した初期実装です。rg の完全互換ではなく、既定が固定文字列検索であること、`--column` が Unicode 文字数であること、JSON スキーマが異なることに注意してください。rg の alias を自動で置き換えることはしません。

`ignore` による並列走査と、行単位のストリーミング読み込みを使用します。ファイル全体をメモリに展開せず、出力キューも 128 件に制限しています。AI モードでは上記の候補バッファと tokenizer のメモリも使います。非常に長い行・大きな文脈指定では、その分のメモリが必要です。日本語正規化には追加の処理が必要なため、rg と同等の速度は保証しません。

```sh
python3 scripts/benchmark.py --binary target/release/jrg
```

ベンチマークは一時コーパスを生成し、ウォームキャッシュでの CLI 起動から検索終了までの中央値と、日本語表記ゆれの一致行数を報告します。詳細と今回の実測値は [BENCHMARK.md](BENCHMARK.md) を参照してください。

## 0.12.0: 文書・出力契約とモジュールの取得

`-e --stream`およびMCPのハイフン開始パターンを値として扱う。文書のreviewは見出し区間（最大120行）か局所文脈を返し、locateへのやり直しを不要にする。既定review探索にMarkdown等を含め、明示ファイルの拡張子は制限しない。コードがある広い探索ではコードを優先し、文書も必要なら同じバッチの別操作でパス/globを指定する。

ファイルのプレビューは先頭固定から、クエリ語を多く含む行を最大16行まで保持する方式へ変えた。製品関数名の語との対応とファイルの大きさも採点し、広いreviewは最上位のsrc/lib/testモジュール系列へ絞る。別系列はhintに残し、明示パスで取得できる。命名規則による推定であり、必要な全モジュールの判定ではない。

JSON/schema調査では、読み込んだコードが64KiB以内なら、必要なソースと同じディレクトリのシリアライズ定義を最大2関数補完する。JSONリテラルの具体的なキーを複数検証するテストも関連候補に加える。既存の実装8/テスト6/補助8/定数16と大きなトークン枠・96,000バイト上限は維持する。関係は字句上の推定で、テスト実行や完全なスキーマ検証を意味しない。

JSON/schemaに直接対応するテストは既存6枠のうち最大2枠を優先する。補完するシリアライズ探索は同一ディレクトリの16KiB以下・最大8候補ファイルに限定し、実際のキー定義を持つ関数を選んでから順位付けする。JSONパーサーの参照だけで出力定義が隠れないようにする。
