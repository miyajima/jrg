# jrg — 日本語の表記ゆれと AI 入力に対応する検索 CLI

Rust 製の再帰テキスト検索ツールです。`がっこう` で `ガッコウ`、`ｶﾞｯｺｳ`、結合濁点の `がっこう` も見つかります。検索結果は元の表記を保ち、一致箇所を元の文字に対応付けて表示します。

AI に渡す結果には **`--ai`** を使ってください。パス共有・重複排除・一致周辺の抜粋と、実際のトークン計測によって出力を抑えます。

```sh
git clone https://github.com/miyajima/jrg.git
cd jrg
cargo install --path . --locked
jrg がっこう ./docs
jrg -i ＡＰＩ -g '*.md' .
jrg --encoding shift-jis 東京 ./legacy
jrg --ai --max-tokens 1000 がっこう ./docs
```

ビルドには Rust 1.88 以降と、対象 OS のビルドツールが必要です。実行時に Rust のインストールは不要です。

## Mac / クラウドへの導入

ソース一式を対象の Mac / Linux に置き、次を実行します。

```sh
sh install.sh
```

`~/.local/bin/jrg` と、AI 出力を既定にする `~/.local/bin/jrg-ai` を導入します。同梱バイナリがそのマシンで動かなければネイティブビルドへ切り替えます。その場合は Rust 1.88 以降と、OS のビルドツールが必要です。Mac では Xcode Command Line Tools、Linux では C リンカなどを用意してください。

```sh
sh install.sh --build                     # 必ず対象マシン上でビルド
sh install.sh --bin-dir /opt/tools/bin    # 導入先を明示
jrg-ai --max-tokens 1000 認証 ./src
```

`~/.local/bin` が PATH に含まれていない場合は、シェルの設定で PATH に追加してください。インストーラはシェル設定や既存の `rg` を変更しません。導入前にバージョンと日本語の AI 検索を確認し、再実行で更新できます。

Codex クラウドでも、リポジトリをクローンした後に `sh install.sh` を実行できます。新規環境でも使うには、各環境のセットアップスクリプトに導入を組み込んでください。実行中の 1 台への導入だけでは、他の既存環境や今後作成される環境へは反映されません。

## AI に渡すトークンを抑える

```sh
jrg --ai --max-tokens 1000 認証 ./src
jrg --ai --snippet-chars 80 -e 東京 -e 京都 ./docs
jrg --ai --regex 'TODO|FIXME' ./src
```

`--ai` は次のように結果を圧縮します。

- パスをファイルの先頭に一度だけ表示する。
- 同じファイル内の完全に同じ原文行をまとめ、行番号を保持する。連続した位置は範囲にする。
- 長い行は最初の一致の周辺を抜粋する。既定は最大 160 書記素、予算が不足すればさらに短くする。
- 一致行を文脈行より優先し、候補ファイルごとに 1 グループずつ順番に予算を割り当てる。
- 全体を `o200k_base` で計測し、ヘッダー・改行・末尾集計も含めて `--max-tokens` 以内に収める。既定は 2,000、指定範囲は 64〜1,000,000。

同じ原文が 1、2、4 行目にある場合:

```text
@ src/auth.rs
1-2,4:1:認証を再試行します
# matched=3 shown=3 omitted=0 clipped=0
```

`行番号:開始列:抜粋` の形式です。開始列は、抜粋本文の最初の文字の、原文での Unicode 文字位置（1 始まり）です。追加した `…` は列に含みません。文脈行には `~` を付けます。制御文字はエスケープし、色コードは出力しません。

- `matched`: 検索で選択した一致行数（`-v` では選択した不一致行数）。
- `shown`: 行番号を表示した一致行数。重複を範囲にまとめた場合も元の行数で数える。
- `omitted`: 予算・候補制限によって出力しなかった一致行数。
- `clipped`: 表示した一致行のうち、本文の一部を `…` で省略した行数。

`omitted=0` でも `clipped>0` なら原文の一部を省略しています。長い行に複数の一致がある場合、後方の一致は抜粋に含まれないことがあります。長い検索語自体も抜粋幅に収まらなければ途中で切れます。予算不足で一部の行番号だけを表示した場合も、残りは `omitted` に計上します。必要に応じて対象ファイルに絞って再検索するか、`sed -n '10,30p' src/auth.rs` などで原文を確認してください。

このモードは検索終了後にまとめて出力します。並列検索でも同じ候補集合なら結果は同じ順序です。候補は最大 4,096 グループ、各グループの位置は最大 256 区間に制限し、超過分も `omitted` に含めます。連続した同一行は位置の区間数を増やさずに保持できます。候補上限に達した場合は、一致行、パス、本文、行番号による辞書順の先頭を保持します。`-m` で検索自体を打ち切った範囲より後の行は `matched` に含みません。

トークン上限は **stdout 本文の `o200k_base` トークン数**です。モデル固有の tokenizer、API のメッセージ枠、stderr のエラー表示などは含みません。通常出力より必ず短くなる保証はなく、ごく少ない一致では集計の分だけ増える場合があります。辞書は実行ファイルに埋め込み、実行時の通信や外部 AI API は使用しません。正確な計測と全件走査のため、通常モードより実行時間とメモリを使います。

通常出力や JSON が必要なら `--ai` を外してください。`--ai` は `--json`、`-c`、`-l`、`-q`、`-o`、`--no-line-number`、`--column` と併用できません。`--max-tokens` と `--snippet-chars` は `--ai` 専用です。

[トークン削減の実測と再現方法](TOKEN_BENCHMARK.md)

## 日本語検索の仕組み

既定では検索語と各行に **NFKC → カタカナをひらがなへ統一** の順で変換を適用し、固定文字列として検索します。

| 検索語 | 一致する表記の例 |
| --- | --- |
| `がっこう` | `がっこう` / `ガッコウ` / `ｶﾞｯｺｳ` / `がっこう` |
| `ＡＰＩ` | `API` / `ＡＰＩ`（`-i` なら `api` も） |
| `株式会社` | `株式会社` / `㍿` |
| `123` | `123` / `１２３` / `①23` |

NFKC は幅や濁点のほか、丸数字・合字・単位記号などの互換文字も統一します。原文との対応には書記素クラスタを用いるため、`が` の一致を `ｶﾞ` 全体に、`社` の一致を `㍿` 全体に対応付けます。同じ原文字への重複した一致はまとめます。

`--no-kana` でカナ統一だけを、`--no-normalize` で両方の変換を無効にできます。英字の大文字小文字は既定で区別し、`-i` で無視します。`-S` は正規化した検索語に大文字が含まれるときだけ区別します。

漢字の読みや同義語は扱いません。`がっこう` と `学校`、`高橋` と `髙橋` は別の文字列です。長音や小書き文字も区別します。

形態素解析による分かち書きや、単語境界を考慮した日本語検索には未対応です。中国語・韓国語も Unicode の文字列として検索できますが、簡体字・繁体字の相互検索など、言語固有の処理は行いません。AI 出力のトークン計測は、検索用の分かち書きとは別の機能です。

## よく使うオプション

| オプション | 動作 |
| --- | --- |
| `-e 語1 -e 語2` | 複数の検索語を OR 検索 |
| `-F` | 固定文字列検索（既定） |
| `--regex 'TODO\|FIXME'` | **原文**に対する正規表現検索。正規化は行わない |
| `-i` / `-S` | 大文字小文字を無視 / スマートケース |
| `-g '*.md'` / `-g '!vendor/**'` | glob による対象指定 / 除外 |
| `--hidden` / `--no-ignore` | 隠しファイルを含める / ignore 規則を無効化 |
| `-l` / `-c` / `-q` | ファイル名のみ / 一致行数 / 終了コードのみ |
| `-o` / `-v` | 一致部分のみ / 一致しない行 |
| `-C 2` / `-B 2` / `-A 2` | 前後 / 前 / 後の文脈を表示 |
| `-m 10` | 各ファイルで選択する一致行の上限 |
| `--column` | 元の行での開始列（Unicode 文字数、1 始まり） |
| `--no-line-number` | 既定の行番号を省略 |
| `--encoding utf8\|shift-jis\|euc-jp` | 入力文字コードを指定（既定 UTF-8） |
| `--json` | JSON Lines 出力 |
| `--ai` | AI 向けの圧縮出力 |
| `--max-tokens 1000` | AI 出力全体の o200k_base トークン上限 |
| `--snippet-chars 80` | AI 抜粋の最大書記素数（16〜4,096） |
| `-j 4` | 並列検索数（既定は利用可能 CPU 数、上限 12） |
| `--color auto\|always\|never` | 一致部分の色付け |

正規表現の実行例は `jrg --regex 'TODO|FIXME' src` です。正規表現では構文を保つため、パターンも検索対象も正規化しません。Rust `regex` の構文を使用し、後方参照や look-around は使えません。

`-e` を使った場合は位置引数をすべて検索パスとして扱います。`jrg -e 東京 -e 京都 docs` は docs 内を検索します。

## ファイルと標準入力

パスを省略すると、標準入力がパイプの場合はその入力を、それ以外はカレントディレクトリを検索します。明示的な `-` も標準入力です。

```sh
printf 'ガッコウ\n' | jrg がっこう
jrg がっこう - docs/notes.txt < input.txt
jrg -e 東京 -e 京都 ./docs
jrg --regex 'TODO|FIXME' ./src
```

ディレクトリは再帰検索し、既定で `.gitignore`、`.ignore`、`.git/info/exclude`、Git のグローバル除外を適用します。Git リポジトリ外の `.gitignore` も有効です。隠しファイルは省略し、ディレクトリ内のシンボリックリンクは辿りません。**肯定の `-g` は明示的な包含指定なので、ignore と隠しファイルの規則に優先します**（rg と同じ挙動）。

UTF-8 BOM と CRLF に対応します。Shift_JIS（CP932）・EUC-JP は `--encoding` で選びます。曖昧な文字コードの自動推定は行わず、不正なバイト列はエラーにします。UTF-16/32 は未対応です。バイナリ判定は初期バッファ（最大 8 KiB）の NUL の有無によるもので、`-a` で無効にできます。

## 出力形式

通常は `パス:行番号:元の行`、文脈行は `パス-行番号-元の行` です。パスは常に出力します。並列処理のためファイルの出力順は不定で、異なるファイルの行が交互に出ることがあります。各行の出力自体は分割されません。

`--json` の例:

```json
{"type":"match","path":"notes.txt","line_number":1,"text":"前ｶﾞ後","submatches":[{"start":3,"end":9,"column":2,"text":"ｶﾞ"}]}
```

`start` / `end` はデコード後の元の行（BOM・改行を除く）の UTF-8 バイト位置で、0 始まり・終端を含まない範囲です。Shift_JIS などの入力バイト位置ではありません。`column` は 1 始まりの Unicode スカラ値の位置で、表示幅・書記素数ではありません。文脈行の `type` は `context` です。

終了コード: **0 = 一致あり、1 = 一致なし、2 = エラー**。`-q` は一致を見つけた時点で 0 を返します。パイプの読み手が閉じた場合も正常終了します。

## rg との関係と性能

これは日本語検索を優先した初期実装です。rg の完全互換ではなく、既定が固定文字列検索であること、`--column` が Unicode 文字数であること、JSON スキーマが異なることに注意してください。rg の alias を自動で置き換えることはしません。

`ignore` による並列走査と、行単位のストリーミング読み込みを使用します。ファイル全体をメモリに展開せず、出力キューも 128 件に制限しています。AI モードでは上記の候補バッファと tokenizer のメモリも使います。非常に長い行・大きな文脈指定では、その分のメモリが必要です。日本語正規化には追加の処理が必要なため、rg と同等の速度は保証しません。

```sh
python3 scripts/benchmark.py --binary target/release/jrg
```

ベンチマークは一時コーパスを生成し、ウォームキャッシュでの CLI 起動から検索終了までの中央値と、日本語表記ゆれの一致行数を報告します。詳細と今回の実測値は [BENCHMARK.md](BENCHMARK.md) を参照してください。

## 開発

```sh
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
cargo build --release --locked
python3 tests/install.py
```

`src/normalize.rs` が正規化と原文位置への対応付け、`src/search.rs` が検索・デコード・文脈処理、`src/output.rs` が通常出力と JSON、`src/ai.rs` が AI 向け圧縮・トークン予算、`src/cli.rs` が引数定義です。MIT ライセンス。
